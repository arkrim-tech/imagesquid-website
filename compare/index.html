Open-source photo library with provenance

ImageSquid, Immich, PhotoPrism, and digiKam, compared on provenance, exit, and archival format only. This page does not compare interfaces, phone apps, or a feature checklist.

Provenance, exit, and archival format

Provenance, exit, and archival format
Library Provenance Exit Archival format
ImageSquid Every import starts a durable C2PA Content Credentials record. It discloses human-generated content, AI-generated content, or both. Prior credentials, generator marks, and later ImageSquid actions stay auditable. Signed statements travel with the file. PROV-O records who did what. Sidecars in the OCFL object can also hold EXIF, Dublin Core, and Schema.org. You can leave the app and any optional sync or backup service without losing original media, later enhancements, or metadata. Export tools make an OCFL bulk copy you can open in a new ImageSquid, with filesystem tools, or in another application on that object store. Files on disk are the canonical source, stored as OCFL objects. A completed library can be read without ImageSquid installed.
Immich Immich's docs describe EXIF and XMP sidecars for description, rating, date, location, and tags, saved to the database. They do not describe C2PA Content Credentials. Original photos and videos are stored unmodified in the upload location. Edited metadata goes to XMP sidecars and Postgres, not into the original file. A restore needs both the files and the database. Metadata added to an external library stays inside Immich unless a sidecar is written. With the default storage template off, library file names are random ids. Original files, a Postgres database, and optional XMP sidecars. Not described as OCFL.
PhotoPrism PhotoPrism's metadata guide describes scanning EXIF, XMP, IPTC, and Google Photos JSON, and writing YAML sidecars. It does not describe C2PA Content Credentials. Except for orientation, edits are not written back into the original files. Originals stay files on disk. YAML sidecars are written so album and photo metadata can be read without the database. Original files, a database, and YAML sidecars. Not described as OCFL.
digiKam The digiKam 9.2 manual describes reading and writing EXIF, IPTC, and XMP, in the file or in an XMP sidecar. It does not describe C2PA Content Credentials. Photographs and videos stay in the root folders you choose, on a disk, a removable drive, or a network share. Metadata can be written into those files or into sidecars. The catalog is a separate database. A folder tree plus a catalog database. When SQLite is used, that database is stored with the collection. Not described as OCFL.
